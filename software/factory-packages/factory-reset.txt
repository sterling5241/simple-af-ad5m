The real flashforge_init.sh (factory-reset variant) - full behavior
-------------------------------------------------------------------------
This is THE actual, complete factory-reprovisioning mechanism (a full
destructive reset/reflash of the persistent application layer,
triggered from USB):

  install_prepare(): safety check - MACHINE must be "AD5X", PID "0026",
    uname -m "mips" (else shows factory-error.raw.xz and exits). Same
    check as ../boot/hardware.txt's naming-gotcha section.

  install_factory():
    - refuses to run if Zmod is currently mounted ("Mod launched.
      Installation is prohibited.") - a real, built-in protection
      against running this while a mod is active.
    - requires >=800MB free on /usr/data (else factory-nospace screen)
    - requires /mnt/AD5X-factory.tar.xz present on the USB drive (else
      factory-notfound screen), copies it to /usr/data/, and requires
      its md5 to match md5.txt exactly (else factory-md5 screen)
    - preserves the real printer serial number (reads
      printerSerialNumber from /usr/prog/config/Adventurer5M.json
      first)
    - WIPES: /usr/prog/logo.jpeg, /usr/prog/etc/, /usr/prog/PROGRAM/,
      /usr/data/logs/*, /usr/data/config/mod_data, /usr/data/config/mod,
      /usr/data/.mod/ (this deletes ALL of Zmod's persistence too, by
      construction, along with the entire real application stack)
    - EXTRACTS: `xz -dc AD5X-factory.tar.xz | tar -xf - -C /` - the
      WHOLE factory.tar.xz payload gets extracted directly onto the
      root filesystem. Since squashfs / is read-only, this really
      means it repopulates /usr/prog (usershare, writable ext4) and
      /usr/data (userdata, writable ext4) from scratch - THE real
      mechanism for restoring/reprovisioning the entire persistent
      application layer, independent of and unrelated to the A/B
      kernel/rootfs OTA slots (see ../boot/ab-slots.txt).
    - re-injects the preserved serial number back into the freshly
      extracted Adventurer5M.json (sed replaces a placeholder
      "SNMQQE9100319")
    - optional second overlay: if /mnt/config.tar also exists on the
      USB drive, extracts that on top too (a documented, real
      user-customization layer separate from the main factory payload)

  Whole thing runs framebuffer status screens throughout, reboots via
  sysrq (`echo b > /proc/sysrq-trigger`) on completion.
